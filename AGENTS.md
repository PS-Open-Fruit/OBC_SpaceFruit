# AGENTS.md

Instructions for AI coding agents (Claude Code, Codex, Cursor, Copilot, and others) working in this repository. Human-facing documentation is in [README.md](README.md) and [docs/](docs/).

## Project in one paragraph

Flight software for a CubeSat-style On-Board Computer: an STM32L496ZG running FreeRTOS. It talks to a ground station over an RF433 radio link (`UART4`, 9600 baud), to a Raspberry Pi camera payload over USB CDC, and to the EPS over `USART2`. Every link uses KISS framing. The Python tools in the repository root (ground station, OBC emulator, sniffer, stress tests) speak the same protocol from a PC. Read [docs/architecture.md](docs/architecture.md) first, and [docs/protocol.md](docs/protocol.md) before touching anything protocol-related.

## Git rules (must follow)

- **Never commit or push unless the user explicitly asks.** When work is ready, suggest a commit title and stop.
- **Prefix-style commit titles:** `<type>: <summary>` or `<type>(<scope>): <summary>`, lowercase, imperative, no trailing period, about 72 characters at most.
  - Types: `feat`, `fix`, `docs`, `refactor`, `test`, `build`, `ci`, `chore`, `perf`, `style`
  - Example scopes: `firmware`, `protocol`, `gs`, `emulator`, `payload`, `eps`
  - Examples: `fix(firmware): send NAK when pi status times out`, `docs: add protocol test vectors`
- **Keep commit bodies short:** none, or one to three plain lines saying *why*. No long change lists. The diff shows *what*, and reviewers need to be able to read it.
- **No AI attribution:** do not add `Co-Authored-By` trailers or "Generated with …" lines to commits or pull requests.
- `dev` is the working branch and `main` is the pull-request target. Do not rewrite pushed history.

## Build and verify

Run commands from the repository root. These work without hardware:

```bash
make -j8                       # firmware -> build/hardware-test.elf (arm-none-eabi-gcc must be on PATH)
python -m py_compile GS.py OBC.py Sniffer.py Shared/Python/*.py
```

Protocol sanity check: a ping request must encode to `C0 00 00 00 00 00 00 47 10 BB 9C C0`. More test vectors are in [docs/protocol.md](docs/protocol.md#example-frames).

These need hardware, or setup only the user can provide. **Do not run them unless the user asks:**

- `program.sh` / `program.bat`: flash the board (needs OpenOCD and an ST-Link)
- `GS.py`, `OBC.py`, and the `test_*.py` scripts: need real serial ports or a virtual pair (com0com / socat)
- `unison_sync.sh`: two-way sync to a remote Raspberry Pi over SSH, so it can change files on both sides
- The ground-station `shutdown` command against real hardware: it powers off the payload

There is no unit-test suite. If you can't verify a change, say so; don't claim it works.

## Firmware conventions

- In CubeMX-generated files (`main.c`, `stm32l4xx_it.c`, `usbd_cdc_if.c`, …), put hand-written code **only between `/* USER CODE BEGIN … */` and `/* USER CODE END … */`**. Anything outside those markers is lost when the code is regenerated.
- Write C that passes MISRA checks: CI runs cppcheck with the MISRA addon on `Core/Src`, `obc-drivers` and `obc-protocols`. Use fixed-width types and explicit casts, and never call `malloc`/`free`.
- **Watchdog:** the IWDG fires after about 480 ms. No task may block longer than that without refreshing it. The downlink UART transmit is capped at 400 ms for this reason.
- Tasks communicate through the existing event flags (`systemStateFlag`, `payloadFlag`), queues and mutexes ([docs/firmware.md](docs/firmware.md#rtos-design)). Don't add busy-waits or long `HAL_Delay` calls.
- `printf` goes through a queue to `UART5` (230400 baud). It is safe in tasks but not in ISRs.

## Protocol changes: keep every copy in sync

The frame format and PIDs are implemented in several places. A protocol change must update all of them in the same change:

1. `Core/Inc/commu_helper.h` and `Core/Src/main.c` (firmware, ground-station link)
2. `obc-protocols/` and `obc-drivers/src/kiss_utils.c` (firmware, payload and EPS links; submodules, so ask first)
3. `Shared/Python/kiss_protocol.py` and `Shared/Python/beacon_helper.py`
4. `GS.py`, `OBC.py`, `Sniffer.py`
5. `eps_and_payload_emulator/kiss_file_transfer/vr.py` and its `kiss_protocol.py` (payload link)
6. `docs/protocol.md`

Facts that are easy to get wrong:

- **CRC** is CRC-32/MPEG-2 (poly `0x04C11DB7`, init `0xFFFFFFFF`, no reflection, no final XOR), computed by the STM32 hardware CRC unit. It is **not** `zlib.crc32`.
- The ground-station and payload links are **big-endian**. The raw EPS reply is **little-endian**.
- The payload-link header has **no SeqNum** byte; the ground-station header does.
- PIDs `0x90`–`0xFF` are reserved for dangerous or irreversible commands.

## Documentation

- When a change affects behaviour, a command, a timing value or a frame layout, update the matching file in `docs/` in the same change.
- If you find a bug you aren't fixing, add it to [docs/known-limitations.md](docs/known-limitations.md).
- Documentation is written in English.

## Environment notes

- The main development machine runs Windows (PowerShell and Git Bash). `*.sh` scripts need Bash; `program.bat` is the `cmd` alternative.
- Python tools import `Shared.Python.*`, so run them from the repository root.
- Clone with `git clone --recurse-submodules`. Two submodules use SSH URLs (see [docs/firmware.md](docs/firmware.md#get-the-source-with-submodules)).
- `.gitignore` excludes `*.jpg`, `*.png` and `*.ioc`. `hardware-test.ioc` is tracked anyway; keep it tracked.
